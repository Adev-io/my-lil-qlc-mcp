# Page 2 (multipage) + reorganized Page 1 + sliders — Design Spec

**Date:** 2026-06-08
**Author:** Ari Klopfer / A_Development
**Status:** approved design (grids signed off; this is the written form)

## Goal

Grow the punk-rock show from one 64-pad page to **two pages** on the same Launchpad
Mini MK3 / dashboard / QLC+ console, switched by the Launchpad **→ / ←** arrows. Every
pad on every page does something, and each row holds one effect type. Add the Virtual
Console faders that are actually compatible with the scene-based show.

Net: page 1 reorganized + filled (64), page 2 new (64), 2 working sliders + GrandMaster.
All generated by `scripts/build-show.ts` as before.

## Pinned QLC+ 4.14.x facts (read from source, not guessed)

- **Multipage VCFrame** (`ui/src/virtualconsole/vcframe.cpp`): enable with
  `<Multipage PagesNum="2" CurrentPage="0"/>` inside the frame. Each child carries
  `Page="N"` on its root tag (`vcwidget.cpp` loadXMLCommon/saveXMLCommon). On page change
  `slotSetPage()` does `setEnabled(false)+hide()` on off-page children and
  `setEnabled(true)+show()` on current-page children; `acceptsInput()` gates on
  `isEnabled()`. **Therefore a page-0 button and a page-1 button bound to the SAME MIDI
  note never both fire — only the visible page's button reacts.** This is what makes pad
  reuse across pages safe. Enable/visible propagates to grandchildren (Qt), so disabling a
  sub-frame disables its buttons.
- **Page navigation input:** `<Next><Input Universe="1" Channel="94"/></Next>` and
  `<Previous><Input Universe="1" Channel="93"/></Previous>` inside the multipage frame.
- **MIDI channel math** (`plugins/midi/src/midiprotocol.*`): CC → QLC+ channel = `cc`
  (no offset); Note → `128 + note`. Launchpad Mini MK3 Programmer mode top arrows:
  **→ = CC 94, ← = CC 93** (confirmed in `Novation-LaunchPadMiniMK3.qxi`). So next-page =
  U1 ch **94**, prev-page = U1 ch **93**. No collision with pads (139–216).
- **VCSlider** (`ui/src/virtualconsole/vcslider.cpp`): `<Slider ID Caption WidgetStyle="Slider"
  InvertedAppearance="false">` with `<SliderMode ValueDisplayStyle="Exact" ClickAndGoType="None"
  Monitor="false">Level</SliderMode>`, `<Level LowLimit HighLimit Value>` wrapping
  `<Channel Fixture="ID">chIdx</Channel>`, and an always-present `<Playback><Function>4294967295
  </Function></Playback>` (ignored in Level mode). `<Input Universe Channel/>` + `<WindowState/>`
  like any widget. **Submaster** mode only scales subscribing widgets, not scene buttons.
- **375Z gobo wheel** (ch6) slot centers: Open 4, G1 11, G2 19, G3 27, G4 35, G5 43, G6 51,
  G7 59. **Color wheel** (ch5) matches existing `HEAD_COLOR`.

## Architecture

The Virtual Console root frame holds two siblings:

```
VirtualConsole
  Frame (root, headerless)
    Frame "GRID"  — Multipage PagesNum=2, header SHOWN (GUI page tabs), Next=U1/94 Prev=U1/93
      page 0 sub-frames:  WASH(solo) HEADS(solo) FX(normal) MASTER(normal)
      page 1 sub-frames:  PARS(solo) BARS(solo) HEADS2(solo) CHASE2(solo) PRESETS(solo)
    Frame "FADERS" — headerless, always visible, right of the grid: Strobe Rate, Heads Zoom
  Properties: GrandMaster (= Master Dim), Size widened for the faders
```

- Sub-frames overlap into one 8×8 grid via `frameBBox` (existing technique), per page. Both
  pages map to the **same 64 pad channels** (`PAD.rows`); multipage isolation keeps them apart.
- The GRID frame's header is shown so the GUI/dashboard operator can click page tabs; inner
  sub-frames stay headerless for the clean overlapping grid.
- **Dual-button model unchanged:** each look = OSC button (U0, CRC) + Launchpad button (U1, pad).
  Both live in the same sub-frame and are page-gated together. Consequence: the dashboard/OSC
  fires looks on the **currently shown page** only (it mirrors whatever page the Launchpad/GUI is
  on). Acceptable — the Launchpad is the primary surface; documented in the manual.
- `Placed` gains a `page: 0|1` field so `frameBBox`, the ASCII grid and the manual render both
  pages. Frame names are unique per page, so page is implied by frame.

## Page 1 — reorganized (rows 0–4 unchanged; rows 5–7 regrouped + 1 fill)

Rows 0–4 keep their current looks and positions. Only the bottom three rows move so each row is
one effect family and the single empty pad is filled.

```
r0 COLOURS   Red Amber Yellow Green Cyan Blue Magenta White                 (WASH solo)
r1 WASHES    Warm Cool Red/Blue UV Mag/Cyan Sunset DeepBlue WhiteStatic     (WASH solo)
r2 HEAD POS  Center Wide CrossX Downstage Upstage TightCenter WideOpen Park (HEADS solo)
r3 HEAD BEAM Breakup GoboCycle Prism ColorCycle RedBeam BlueBeam OpenSpot HeadsBO (HEADS solo)
r4 CHASES    Rainbow Police StrobeColor BarChase Bounce SlowCycle AltFlash BuildDrop (WASH solo)
r5 MOVEMENT  HeadSweepSlow HeadSweepFast HeadCircle AudienceSweep CrossZigzag PixelBounce BarScroll ParRun
r6 DYNAMIC   ParsAuto BarsAuto ParsMorph BarsMorph ColorStab KillStrobe ParkAll BarBounce(NEW)
r7 FX+MASTER StrobeAll Blinder UVPop ColorBurst FullOn SoundActive Blackout Panic
```

- Row 5 = HEADS-solo (sweeps/circle/audience/zigzag) + WASH-solo (PixelBounce/BarScroll/ParRun)
  buttons, overlapped at r5 c0–c7. Mixed frames in one physical row is fine — the existing grid
  already overlaps frames per cell.
- **New look (1):** `Bar Bounce` — `addChaser("Bar Bounce", ["Bar Step 1".."Bar Step 4"], 140, 0,
  "Forward", "PingPong")`. Reuses the existing Bar Step scenes; fills r6 c7; fits the dynamic row.
- ParkAll/Blackout/Panic and FullOn/SoundActive land on r7 with the FX flashes. Rows 6–7 are
  "grouped" families (dynamic; impact/master) — best-effort per the "try to keep one type per row"
  note, since master+FX don't make a clean 8.

## Page 2 — new, all 64 filled, one type per row

`Pars/Bars` colour scenes touch **only** their group's channels, so the three colour groups are
independent (PARS solo, BARS solo). Heads do one look at a time (HEADS2 solo holds colour + gobo +
movement), matching page 1's "one head look" model; the per-group requirement is met at the
pars/bars/heads-group level.

```
r0 PARS col   Pars Red..White            (PARS solo)   pars.map(parVal(COLORS[i].par))
r1 BARS col   Bars Red..White            (BARS solo)   bars.map(barVal(COLORS[i].bar))
r2 HEADS col  Heads White Orange Lime Cyan Red Green Magenta Yellow   (HEADS2 solo)
r3 HEADS gobo Gobo1..Gobo7 Prism         (HEADS2 solo)
r4 HEADS move HeadCircle AudienceSweep CrossZigzag HeadSweepSlow HeadSweepFast Figure8 PanWave TiltDip (HEADS2 solo)
r5 CHASES 2   RainbowFast StrobeRainbow ChaseUp ChaseDown TwoTone ParSparkle ColorPop MegaBuild (CHASE2 solo)
r6 PRESETS A  Song 1..8                  (PRESETS solo)  full-stage scenes
r7 PRESETS B  Song 9..16                 (PRESETS solo)  full-stage scenes
```

Content detail (all pan/tilt/gobo are **starting values**, same placeholder status as the existing
POSITIONS table — tuned on the real rig):

- **r0 Pars colour (8):** scene `pars.map(f => parVal(f.id, COLORS[i].par))`, names `Pars <Colour>`,
  LED = `COLORS[i].led`. Bars/heads untouched → independent of BARS/HEADS2.
- **r1 Bars colour (8):** scene `bars.map(f => barVal(f.id, COLORS[i].bar))`, names `Bars <Colour>`.
- **r2 Heads colour (8):** full centred open beam in each wheel colour — `heads.map(headVal({pan:128,
  tilt:128,dim:255,shutter:OPEN,color:HEAD_COLOR[x],gobo:0,focus:128,zoom:128}))`, names `Heads <Colour>`.
- **r3 Heads gobo (8):** `heads.map(headVal({pan:128,tilt:128,dim:255,shutter:OPEN,color:white,gobo:G,
  prism:0,focus:128}))` with G ∈ {11,19,27,35,43,51,59}; `Prism` = gobo 0 + prism 10. Names `Gobo 1..7`,
  `Prism`.
- **r4 Heads movement (8):** REUSE existing functions `Head Circle, Audience Sweep, Cross Zigzag,
  Head Sweep Slow, Head Sweep Fast` (page-2 buttons reference the same Function IDs), plus 3 NEW
  chasers built like the existing CIRCLE/SWEEP tables:
  - `Figure 8` — 6 pan/tilt steps tracing ∞ (both heads synced), ~180 ms, fade 600.
  - `Pan Wave` — heads pan opposite directions across centre, 4 steps, ~220 ms, PingPong.
  - `Tilt Dip` — tilt down→up, pan centred, 4 steps, ~260 ms, PingPong.
- **r5 Chases 2 (8):** NEW chasers over EXISTING scenes (no new scenes):
  `Rainbow Fast`(Red..Magenta @140), `Strobe Rainbow`(Red White Blue White Green White @90),
  `Chase Up`(Bar Step 1..4 @120), `Chase Down`(Bar Step 4..1 @120),
  `Two Tone`(Red Blue Split, Magenta Cyan @500), `Par Sparkle`(Par Px 1..10 @90),
  `Color Pop`(Stab Hit, PB Off, White Hit, PB Off @130), `Mega Build`(Bld 1..4, Bld Peak, PB Off @170).
- **r6–r7 Song presets (16):** `PRESETS` data table of 16 `{name, par[6], bar[3], hColor, hGobo,
  l[2], r[2], led}`; scene = `washVals(par,bar)` + `heads.map(headVal({pan,tilt,color,gobo,dim:255,
  shutter:OPEN,focus:128}))`. Names are song-moment labels (Opener, Verse Blue, Chorus Warm,
  Breakdown UV, Anthem White, Half-Time Red, Build, Drop, …16). Full-stage, solo (one song look).

## Sliders (FADERS frame) — scoped to what works with the scene model

- **Strobe Rate** — Level, channels: par ch7 (fix 0–9), bar ch9 (10–13), head ch11 (14–15).
  `LowLimit 0 HighLimit 255 Value 0`. Scenes leave strobe at 0, so this is a clean strobe master.
- **Heads Zoom** — Level, head ch14 (14–15). `Value 128`. Overrides position-set zoom.
- **Master Dim** — the built-in **GrandMaster** already in `<Properties>` (top-right of the VC,
  `ValueMode="Reduce"`); it is the only fader that truly attenuates intensity. Documented, no new widget.
- Each new slider gets an OSC input (U0, CRC of `/strobe_rate`, `/heads_zoom`) for future dashboard
  wiring; harmless to GUI use.

**Deferred (explicit, not shipped blind):** per-group **Pars Dim / Bars Dim / Heads Dim** faders.
They require removing the dimmer set from every scene so a fader can own intensity, which breaks the
`PB Off`/`parOff` (dim=0) steps that Color Stab / Kill Strobe / Build Drop / Pixel Bounce / Par Run /
Bar Bounce rely on under HTP. That is a show-reliability risk 5 days before the gig. Tracked as a
follow-on intensity rework the user can opt into; not part of this build.

## Generator changes (`scripts/build-show.ts`)

1. New scenes/chasers: `Bar Bounce` (p1 fill); page-2 par/bar/head colour scenes; head gobo scenes;
   `Figure 8` / `Pan Wave` / `Tilt Dip` movement (new step scenes + chasers); 8 page-2 chasers
   (reuse scenes); 16 `Song` preset scenes. Via compact data tables + loops (no hand-written XML).
2. `Placed` + `BtnSpec` gain `page: 0|1`. `emitDualButton` stamps page; page-2 buttons reuse
   `padCh(row,col)`.
3. Page-1 reorg: update the row 5–7 `emitDualButton` padRow/padCol for movement/dynamic/master looks
   per the table above.
4. New page-2 sub-frame button lists (PARS/BARS/HEADS2/CHASE2/PRESETS) emitted like the page-1 ones.
5. VC restructure: wrap all sub-frames in a multipage `GRID` frame (`<Multipage PagesNum="2"…/>` +
   `<Next>/<Previous>` inputs, header shown); add `Page="0|1"` to each sub-frame; add a `FADERS`
   frame with the 2 sliders; widen `<Size>`. New `sliderXml()` emitter; `frameXml` gains optional
   `page` + `multipage`/`nav` params.
6. PATCH-CHART.md `gridAscii()` and the manual render **two** 8×8 grids (page 0, page 1) + a faders
   note + the → / ← page-switch note.
